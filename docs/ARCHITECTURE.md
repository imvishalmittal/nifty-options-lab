# Architecture

## Current system

The repository has two user-facing paths plus shared research automation.

```text
                    ┌────────────────────────────┐
                    │ Legacy learning dashboard  │
                    │ /                          │
                    └──────────────┬─────────────┘
                                   │
Groww market data ──> research / paper engines ──> validated trade ledger
                                   │                     │
                                   │                     └─> /paper dashboard
                                   └─> GitHub Actions workflows
```

## Components

### Legacy learning UI

`app/page.tsx` remains the V0.1 educational dashboard and does not drive the automated paper strategy.

### Paper dashboard

- `app/paper/page.tsx`: paper route.
- `app/paper-ledger.tsx`: sortable/filterable ledger.
- `public/paper/trades.json`: historical accepted rows plus completed forward paper rows.
- `public/paper/session-status.json`: latest paper-session status.

The ledger now distinguishes strategy versions and can display entry/peak/exit premium, maximum favorable move, trail step/gap, breakeven status, final stop, exit reason, stop adjustments, gross P/L, charges, and net P/L. Older rows display missing non-recorded V3 fields as `—`.

### Deterministic paper engine

- `paper/paper-engine.mjs`: current forward-paper mechanics.
- `paper/run-session.mjs`: Groww-backed weekday paper session.
- `paper/groww-paper-client.mjs`: shared cross-process throttling, short-lived response caching, and canonical one-minute candle normalization.
- `paper/paper-contract-selection.mjs`: complete 50-point NIFTY strike-grid discovery, including auditable gap-filled symbols when Groww's contract catalogue is sparse.
- `paper/replay-session.mjs`: deterministic causal recovery for sessions that ended with a data/infrastructure status.
- `paper/build-ledger.mjs`: historical artifact normalization.

The paper engine processes only completed one-minute candles for close/high/low-dependent decisions. Any stop generated by a completed bar is effective only from the following bar.

### Historical research

`research/` preserves V1 and V2 engines and adds V3 stepped-trail research:

- `nifty-180-momentum-trail.mjs`: preserved V2 full-session trail.
- `nifty-180-stepped-trail.mjs`: V3 stepped stop engine.
- `groww-backtest-nifty-180-stepped.mjs`: actual-contract 5-vs-10 step comparison.
- `stepped-result-integrity.mjs`: V3 completeness gate.

V3 shares V2's contract-selection/signal/entry family, keeps a 20-point trailing gap, and compares 5-point and 10-point peak steps. Forward paper uses the 10-point-step candidate unless a later explicitly versioned decision changes it.

## GitHub Actions

Active workflows are limited to:

- `CI`: lint/build/site tests and strategy regression tests.
- `NIFTY Paper Session`: one continuous weekday paper job starting around 09:20 IST.
- `NIFTY Paper Post-Close Recovery`: a guarded 15:40 IST replay that runs only when the live session is non-terminal. It requires a passing integrity report and cannot overwrite `CLOSED`, `NO_TRADE`, or `AMBIGUOUS` live outcomes.
- `NIFTY Paper Smoke`: manual paper/Groww operational validation.
- `Research - NIFTY ...`: four isolated opportunity backtests, their suite chain, and comparison.

Historical NIFTY 180, opening-range, Quick Flip, Stocks-in-Play, backfill, and diagnostic engines remain reproducible from versioned code and Git history without cluttering the active Actions inventory. Groww-heavy active research jobs share a serialized API concurrency group.

## Data flow — historical V3

```text
Groww historical spot/options
        ↓
actual expiry + contract discovery
        ↓
09:25 ₹180 candidate selection
        ↓
completed-1m crossing + next-bar entry
        ↓
5-point and 10-point stepped trails
(same 20-point gap)
        ↓
modeled costs / slippage
        ↓
monthly integrity gate
        ↓
accepted research artifact
```

## Data flow — forward paper

```text
weekday GitHub Actions session
        ↓
Groww market-data API
        ↓
09:25 contract selection
        ↓
completed 1m ₹180 signal
        ↓
next-bar simulated entry
        ↓
₹160 initial stop
        ↓
10-point peak steps / 20-point gap
        ↓
stop or 15:29 session exit
        ↓
gross P/L - modeled charges = net P/L
        ↓
append versioned PAPER row + status
```

No broker-order endpoint exists in this workflow.

## Trust boundaries

1. Provider data must be available and internally consistent.
2. Research/paper rules are deterministic and versioned.
3. Integrity gates decide whether artifacts are accepted as evidence.
4. The ledger must not silently mix strategy versions or promote failed/partial research.
5. Public hosting is a separate release state from GitHub source.

## Hosting

The web app is a Vinext/Vite application with a Cloudflare-compatible worker artifact and OpenAI Sites integration. `.openai/hosting.json` preserves the existing Sites project identity. GitHub CI validates the build; publishing the public `chatgpt.site` build remains a separate hosting action.
