# Architecture

## Current system

The repository now has two user-facing paths plus shared research automation.

```text
                    ┌────────────────────────────┐
                    │ Legacy learning dashboard  │
                    │ /                          │
                    │ screenshots + manual facts │
                    └──────────────┬─────────────┘
                                   │
                                   │
Groww market data ──> research / paper engines ──> validated trade ledger
                                   │                     │
                                   │                     └─> /paper dashboard
                                   │
                                   └─> GitHub Actions workflows
```

## Components

### Legacy learning UI

`app/page.tsx` remains the V0.1 educational dashboard. It previews chart screenshots locally, lets the user verify chart facts, and explains deterministic WAIT/NO-TRADE/READY states. It does not drive the current automated paper strategy.

### Paper dashboard

- `app/paper/page.tsx`: paper trading route.
- `app/paper-ledger.tsx`: sortable/filterable ledger UI.
- `public/paper/trades.json`: validated historical rows plus completed forward paper rows.
- `public/paper/session-status.json`: latest paper-session status snapshot.

The ledger supports year/month/CE-PE/profit-loss filters, row numbering, sorting on displayed columns, and alternating row styling.

### Deterministic paper engine

- `paper/paper-engine.mjs`: pure strategy mechanics for signal, next-bar entry, initial stop, causal trailing stop, gap handling, session exit, and lot sizing.
- `paper/run-session.mjs`: Groww-backed weekday forward paper session.
- `paper/build-ledger.mjs`: converts integrity-passed research artifacts into the dashboard ledger.

The engine processes only completed one-minute candles for decisions that depend on a bar's high/low/close. A stop generated by a bar is effective from the next bar.

### Historical research

`research/` contains V1 and V2 strategy engines, Groww historical-data runners, transaction-cost modeling, integrity checks, and robustness/statistics tooling.

V2 reuses the V1 actual-contract selection/entry family but replaces the fixed target/09:45 exit with a full-session causal trailing-stop path.

## GitHub Actions

GitHub is both the durable code/research journal and the execution environment for research/paper automation.

Important workflows:

- `CI`: lint/build/site tests plus paper-engine regression coverage.
- `NIFTY 180 Momentum 2025`: development research by month.
- `NIFTY 180 Momentum 2026`: holdout research by month.
- `NIFTY Paper Session`: starts one continuous paper job around 09:20 IST on weekdays and keeps it alive through the session rather than relying on one-minute cron scheduling.
- `Paper Ledger Backfill`: downloads validated artifacts and persists normalized dashboard rows.

Groww-heavy jobs use a shared serialized API concurrency group so multiple backtests do not hammer the provider simultaneously.

## Data flow — historical

```text
Groww historical spot/options
        ↓
actual expiry + contract discovery
        ↓
09:25 ₹180 candidate selection
        ↓
completed-1m signal / simulated next-bar entry
        ↓
full-session momentum engine
        ↓
modeled transaction costs + slippage stress
        ↓
monthly integrity gate
        ↓
validated artifact
        ↓
ledger backfill
        ↓
/public/paper/trades.json
```

## Data flow — forward paper

```text
weekday GitHub Actions session
        ↓
Groww current/historical-candle API
        ↓
09:25 contract selection
        ↓
completed 1m ₹180 signal
        ↓
next-bar simulated paper entry
        ↓
₹160 initial stop
        ↓
₹220 activation → 20-point causal trail
        ↓
stop or 15:29 session exit
        ↓
modeled net P/L
        ↓
append PAPER row + status
```

No broker-order endpoint exists in this workflow.

## Trust boundaries

1. **Provider data** must be available, fresh enough for the intended operation, and internally consistent.
2. **Research/paper rules** are deterministic and testable.
3. **Integrity gates** decide whether an artifact may be treated as evidence.
4. **Ledger/dashboard** displays accepted results; it must not silently promote failed/partial research.
5. **Hosting** is separate from GitHub source state: current code can be on `main` while the public ChatGPT Sites deployment still serves an older build until republished.

## Hosting

The web app is a Vinext/Vite application with a Cloudflare-compatible worker artifact and the OpenAI Sites integration. `.openai/hosting.json` preserves the existing ChatGPT Sites project identity. GitHub CI validates the site build; publishing the public `chatgpt.site` build is a separate hosting action.
